## Round 1 report (summary)

- **[Critical] Instrumentation was gated and scored, but agent code can forge or suppress it:** reload pandas or use `.loc` to hide row loss; post fake records to raise trap detections and plant lessons.
- **[Critical] Test rows leak through derived data:** a folder grant (against D-009) or a still-visible derived view lets a predictive analysis train on its own test rows.
- **[Major] Architecture:** no named writer for derived files, catalog entries or lineage; lineage parents undefined for multi-execution variables.
- **[Major] Decisions:** the 1M-row rule (D-031) and the missing `sampled` check; a prose-reading check (D-036).
- **[Major] Recommendations:** DuckDB joins invisible to pandas instrumentation; a plan opt-out for join explosion; imputation false positives; size + mtime change detection.
- **[Major] Operability:** no commit protocol across three processes; compare lanes see each other's data; catalog rebuilds could drop the train-only lockdown.
- **[Major] Measurability:** PA-04 and PA-03 sources undefined, PA-04 passes at 0/0; EC15-2 circular.
- **[Major] Safety:** agent-written names and descriptions as a persistent injection vector; agent-crafted Parquet parsed by a keyed process.
- **[Major] Statistics:** statistics fitted on all rows reused after a later split; wrangling in predictive analyses never reaches test rows; sampled datasets reused as raw.
- **[Major] Completeness:** no stated spend; "wrangling tasks on dev" vs the fixed dev set.
- **Minor/Nit:** row cap, mixed-type conversion, snapshot cap, naive timestamps, channel class for instrumentation, unverified Parquet libraries, reload after restart, catalog ids, D-010 exception, EBUSY, uuid ids, renumbered work items, schema location, field names, model parent, done-when lines, deliverables, terms, Q9 rationale.
