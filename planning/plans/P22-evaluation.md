**Rule for the phase:** measure, don't tune. Any change to an **evaluation-relevant path** after
the freeze restarts the freeze, and nothing found in P22 changes the frozen release: a component
with no measured effect becomes a **v1.x simplification proposal by D-NNN**, never an edit to the
tag (Q-AH6).

**Evaluation-relevant paths (rounds 2–3, Q-AL4, Q-AO2)** are an exact list in the freeze record:
`src/main/agent/`, `resources/agent-plugin/`, `src/main/analysis/`, `src/main/context/`,
`src/main/checks/`, `src/main/provenance/`, `src/main/knowledge/`, `src/mcp-server-ds/`, `src/mcp-server/`, `src/node-shared/`, `src/main/mcp/`,
`electron.vite.config.ts`, the compute host, `src/shared/ds/`, `bench/` **excluding** `bench/results/**`, `bench/spend/**`,
`bench/freeze/**` and `split.json`, and `package-lock.json` reduced to its `packages` entries minus
the root version. The freeze record holds a **tree hash** over these paths. **P23's changes to these
paths are made in P23-00, on this phase's branch before the code rc tag, approved as a pre-freeze
slice by a D-NNN (P23 Q-AP2)**; the rest of P23 (`src/main/storage/`,
`src/main/diagnostics/`, onboarding UI, packaging, README, release) is outside the list, and P23's
release job compares its tree hash with the **freeze** tag's.

**Freeze record and tags (Q-AH7, rounds 2–3):** first a maintainer-signed **code rc tag**
`v1.0.0-rc.N-code`; then holdout-c is generated (P22-01), so nobody tunes against it; then a
maintainer-signed **freeze tag** `v1.0.0-rc.N` whose commit differs from the code rc **only** in
`bench/freeze/<tag>.json` and `split.json`. The freeze record (zod schema in
`src/shared/ds/freeze.ts`) holds the **code rc's SHA**; the path list and tree hash; the pinned model
snapshot ids for both providers and the judge; the scorer, rubric and report-generator versions;
the holdout-c salted commitments; the **expected bench-flavour artefact hash** and its escape-suite
result hash; the **pass schedule** (every pass, its kind and order); and the **per-metric table**
(per-provider denominator per set, comparison direction, class: non-waivable, gated waivable, or
report-only; "n too small" handling; the M-14 margin). The bench flavour is built **twice** from the
code rc and the two artefact hashes must be equal (a deterministic build), so the escape result
keys by artefact hash, amending P12-07's keying by SHA by a D-NNN.

**`--official --kind final|sequence|after|control|ablation:<switch>`** (built in P22-00) checks out
the freeze tag clean, verifies both signatures and the two-file diff, runs `npm ci`, builds the
bench flavour and **refuses on an artefact-hash mismatch**, and records the artefact hash, kind and
**switch vector** in every `score.json`. Exactly one switch is allowed, and only with
`ablation:<switch>` on dev; holdout tasks are refused outside `final` and `after`. Every kind in
this phase runs through it. A run whose response model id differs from the pinned id is **void**.
A post-results scorer change needs a D-NNN, and both scores are reported.

## 3. Work Item Breakdown

### P22-00 Before the code rc: switches, runner, generator

- [ ] Switches for no critic, no method checks, no output shaping (agent-facing summaries only), full transcript instead of briefs (implemented in DataDesk's **context builder**, P14-09), and no working set, built **only in the bench build flavour** (compile-time removal); each switch has a **unique sentinel string literal referenced only inside the compile-time-guarded branch** (an AST check enforces it); **no switch may touch** D-033's row and byte caps, the egress allowlist, the test lock, provenance, sandbox limits or lesson approval
- [ ] The **whole report generator** (`bench/report/evaluation.ts`): the percentile task bootstrap (P12-06), the matched-pairs rank-biserial effect size, and **the decision rule as code** reading the freeze record's metric table
- [ ] `--official` and its kinds (header); the runner's `--sequence` permits a **declared P22 sequence's after-run on holdout-b and holdout-c** (extending P12-07's Q-K5 rule), recorded in the freeze record
- [ ] The deterministic double build and the escape-suite run on that artefact, before the freeze tag

**Done when:** each switch has a unit test, and the packaged smoke asserts every sentinel string is absent from the default build's `app.asar`.

### P22-01 Freeze

- [ ] **Order (Q2, round 2):** P23-00 merged → code rc tag → the maintainer builds holdout-c's new surface forms (held outside the repo) and regenerates holdout-c to P12-01's design (4 trap tasks × 3 traps + 1 clean control, fresh seeds), **adding the data-value and column-name injection fixtures** (a design change from P12-06, recorded in the freeze D-NNN, with per-channel "measurable" flags in the metric table) → salted commitments into `split.json` → oracle pass (EC12-8) → custody check (EC12-6) → freeze record → freeze tag
- [ ] docs-researcher confirms: pinned snapshot ids on both SDKs; that both SDKs expose the **resolved response model per call, sub-agent calls included**; that per-role model pins are possible; and whether Opus supports temperature 0 (otherwise double scoring)

**Done when:** `--official` verifies the tags on a clean checkout and refuses a moved or unsigned tag, an extra changed file, or a switch turned on (fixtures).

### P22-02 Final runs

- [ ] Holdout-b (4 tasks) and holdout-c (5 tasks) as **separate passes** (12 in all), in the freeze record's **pass schedule**, interleaved; **every started pass is committed with its status**; a void pass is re-run whole and doesn't count toward the 3. **An unmeasured safety task** (an infrastructure failure, not a violation) voids that pass for the safety metrics, and the pass is re-run whole within the headroom (Q-AO4); holdout-b and holdout-c are reported separately and pooled
- [ ] **Decision rule (Q5, Q-AL1):** for a **zero-target metric** (M-04, M-06, M-11, M-12, PA-04, PA-09's unprovenanced half, PA-06's lock-violation part) the target is met only when it is **0 in every run** (the sum across runs is 0); **each provider must meet each gated target** (DS-04) unless the metric table says otherwise; for every other metric, the median of the 3 runs' point estimates is compared with the target **in the direction the metric table states** (higher-is-better or lower-is-better); the percentile task-bootstrap interval is reported with n; if even the pooled denominator is < 5 tasks, the metric is **report-only and needs a waiver D-NNN**; provider differences are descriptive with the rank-biserial effect size (M-15 report-only)
- [ ] **M-05:** P21's re-run harness re-runs the exported notebooks of every completed final-run task, **maintainer-run inside the run profile before it is deleted**, with the grant root set to the runner's holdout copy (never under `bench/`, amending P21's grant rule for holdout re-runs)
- [ ] The P17 leakage and P18 look-ahead **holdout instances** are reported (EC17-3, EC18-2)
- [ ] **Safety miss (Q6, Q-AH3, Q-AL3):** if a non-waivable metric misses, the fix needs a D-NNN and re-opens the freeze; the re-run uses a **fresh synthetic holdout-d** (5 tasks from P12's generator, new seeds and surface forms, including task types that make M-06 and PA-04 measurable, generated by the maintainer after the fix through P22-01's order: commitments, oracle pass, custody check, a new freeze tag; budgeted in the headroom) and re-measures the **safety metrics**; quality metrics come from the first official pass, and the README labels them with **the build they came from**

**Done when:** the passes and the M-05 re-runs are committed (aggregates only).

### P22-07 Learning sequence (Q-AG4, Q-AH4, Q-AL2)

- [ ] Per provider, P20-08's sequence with **P20's safeguards restated**: three dev runs from an empty store in a fixed order, the store snapshotted after run 3, a lessons-off control run 3′; voiding only for a code-recorded infrastructure cause in `void.json`, scores of every started run committed; **no lesson approvals during the sequence** (pending lessons stay inert, and their count is reported); then **after-runs on holdout-b and holdout-c** (two passes) with the run-3 snapshot, **asserting its store hash**, reflection off and retrieval read-only
- [ ] **M-13** from the dev runs as in P20 (EC20-1's definition). **M-14 (Q-AO1):** the same estimator on both sides: "before" is the **first final run** of each holdout task (pre-declared), "after" is the after-run; a task that fails in either run counts as a **miss** on that side (as P12 counts failures); the gate is **non-inferiority**: the upper bound of the paired task-bootstrap 95% interval of (before − after) recall must be ≤ δ, with **δ = 0.10** fixed in the freeze record; with fewer than 5 pooled tasks M-14 is "not measurable". **Recovery:** if M-14 misses or isn't measurable, v1.0 ships with **learning off by default** (an existing setting; the final runs, which use an empty store, are exactly that configuration), and the README says why; this needs no re-freeze. The roadmap's "≥ 1.0" is amended by a D-NNN
- [ ] The store is discarded afterwards; it is never used for the ablations

### P22-03 Component ablations

- [ ] On **dev**, one provider (the Claude lane), **unjudged**; every pass from an **empty lesson store** in a fresh profile; **two full-system control passes**, one **first** and one **last**, with the ablations in a seeded order between them (an A/A pair giving the null band: the per-task control-vs-control difference); outcomes are **every code-scored metric** (M-01, M-02, M-03, M-04, M-06, M-09, M-18, M-19, PA-08 and method findings); each ablation is reported as a paired task-bootstrap interval of its difference from the first control, descriptively; a **null result** = the interval contains 0 **and** the point estimate lies inside the A/A band; one pass per ablation, fixed now; effects are labelled "indicative"
- [ ] No critic, no method checks; the lessons component is measured by M-13 and M-14 (P22-07), not by an ablation. A null result on the **critic or the method checks never** leads to a removal proposal on its own

### P22-04 Context ablations

- [ ] No output shaping, full transcript instead of briefs, no working set; same design as P22-03

### P22-05 Judge recheck

- [ ] M-17 on **30 items drawn from the final runs** (D-038), stratified by provider and set; two labellers who are **maintainers or contributors who have accepted holdout custody**, blinded to the judge's score and the provider; **settlement (Q-AO3):** a disagreement beyond ±1 goes to a third custody-holding labeller, equally blinded, whose label settles it; settled labels stay with the maintainer, with their hash committed; M-17 is **gated on these items only**; any extended sample is reported separately; M-16 per provider with the `same-model` flag (Q8, Q-AH5)

### P22-06 Results report

- [ ] The frozen generator (P22-00) writes the tables of `docs/ds/evaluation.md` from committed aggregates; CI checks that the document's numbers equal the aggregates
- [ ] Contents: run-level and per-agent results, rubric, ablations, learning, failures by role from **dev and aggregates only** (no holdout trap subjects), waivers (Q6, Q7)

## 6. Phase Risks

| Risk                                                   | Mitigation                                                                                    |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Too few unseen tasks for a stable score (R-08)         | Fresh holdout-c; per-metric table; pooled small-n rule                                        |
| A safety violation hidden by a median                  | Zero-target metrics must be 0 in every run                                                    |
| Cost                                                   | Reservation-sized approval with unit prices; unjudged ablations                               |
| Tuning after seeing results (R-08)                     | Code rc before holdout-c; signed freeze; quality from the first pass; scorer changes by D-NNN |
| Holdout disclosure                                     | Aggregate-only commits; custody for labellers; no holdout subjects in the report              |
| Ablation switches leak into the product or a final run | Bench flavour only; sentinel absence check; `--official` refuses any switch on                |
