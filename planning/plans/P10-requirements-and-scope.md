- [ ] **Verdicts computed by code, not by the agent (audit A, Critical).** `/review-suite` runs each criterion **in its own subagent** at the model mapped in `.claude/agents/reviewers/tiers.json`, **loading the criteria and `tiers.json` from the PR's base branch** (`git show <base>:…`), so a PR's own criterion edits take effect only after it merges (R3-7). Each criterion returns **zod-validated JSON**: `{criterion, status: pass|fail|n/a, subScore 0–5, findings[]}`. `scripts/review/aggregate.mjs` (code) computes `weight × subScore / 5`, excludes `n/a`, decides which blockers fired, and writes `docs/reviews/<pr>/verdict.json` (zod schema in `scripts/review/`, dev tooling outside the product tree) plus a rendered `verdict.md`. Both record the **reviewed commit SHA**, the **diff hash**, and the **SHA-256 of every criterion file**.
- [ ] **Applicability decided by code.** A path map in `scripts/review/applicability.json` (a protected path; e.g. `src/main/**` → 01; `src/shared/**` → 05; `subagents.ts` and agent options → 04) decides which blocker criteria apply to a diff. A blocker that applies may not return `n/a`; code rejects it, so a comment in the diff can't talk a criterion into `n/a` (audit G2).
- [ ] **CI re-verifies, and needs no key.** CI runs the **base branch's** copy of `scripts/review/` (so a PR can't change the code that judges it), recomputes the diff hash from the reviewed SHA, checks that only `docs/reviews/**` changed after it, checks the criterion-file hashes equal those on the PR's **base branch** (so a PR can't edit the criteria that judge it), re-runs the aggregation script on the committed criterion JSON, and runs every **mechanical** check itself as deterministic scripts (weights sum to 100, conventional commits, `DECISIONS.md` append-only, `--save-exact` pins, traceability, the spend ledger).
- [ ] Changes to `.claude/agents/reviewers/**`, `tiers.json` or `scripts/review/**` are protected paths, so they need code-owner approval (Q-A1, DS-23).
- [ ] **Fail closed:** a criterion that times out, returns invalid JSON, or is missing counts as a **fired blocker** whenever that blocker applies.
- [ ] **Bootstrap:** the PR that first introduces the suite has no criteria on its base branch to compare against. It is reviewed with `code-reviewer` plus code-owner approval, and that exemption is recorded in its verdict.
- [ ] A forged **`pass`** from a judgement criterion can't be detected by code alone. That residual risk is covered by code-owner review of protected paths, and that protection is the CODEOWNERS set in P10-08 plus human peer review (Q-B1, Q-B2).
- [ ] `08-context-and-cost` becomes a **blocker**: it checks that any paid-run code path goes through the runner's approval check (DS-21). The runner's code enforces the money limit; `bench/spend/<phase>.jsonl` is evidence only.
- [ ] **Precedence:** any blocker → REQUEST CHANGES, whatever the score. The score is advisory and shown as a trend; the bands (90+, 75–89, 60–74, < 60) are labels, not gates.
- [ ] **PR order:** open a draft PR (so it has a number) → run `/review-suite` → commit the verdict under `docs/reviews/<pr>/` → mark ready → peer review → a human merges. When P10-09 lands, the review-verdict check becomes a required status check (R3-13).
- [ ] A tooling test fails if the weights stop summing to 100 or a criterion lacks `weight`, `blocker` or `tier`.
- [ ] The existing `code-reviewer` agent's checks are split into criteria 01, 02 and 09, and `/finish-phase` runs `/review-suite` on the phase PR instead.

**Done when:** a **fixture set of planted violations, at least one per CLAUDE.md rule 1–6**,
is each detected (REQUEST CHANGES naming the right blocker) in **3 of 3 runs**; a fixture set of **≥ 5 clean PRs passes 3 of 3** (false-positive check);
a hand-edited verdict and an edited criterion file are both rejected by CI.
**Depends on:** Q41, Q-A1, Q-A2, Q-B1, Q-B2.
