## Round 1 report (summary)

### A. Architecture

- **[Critical]** The baseline had no input the scorer can read: today's SQL analyst writes no journal, no key-results block and no role attribution, so EC12-3, DoD-4 and P12-12 couldn't be computed on it.
- **[Major]** Two answer schemas with no owner: Q6's answer block with `issues[]` vs P11-09's key-results block.

### B. Decision compliance

- **[Critical]** The runner contradicted D-034 (`--confirm` above the cap; no remote approval, typed id, agent-session or non-TTY refusal, ledger or per-contributor entry; judge spend outside the runner; no stated phase amount).
- **[Major]** Holdout custody contradicted D-036 (task files and `split.json` committed; "refuse unless P22" vs holdout-a in P20).
- **[Major]** Q10's `same-provider` label vs D-038's `same-model` rule; plural judge ids.
- **[Major]** D-036's CI re-scoring missing; Q9's "raw outputs stay local" vs P10 Q44.
- **[Major]** M-19 and the bootstrap interval missing.
- **[Major]** Rule 5: the runner would copy the e2e fixture's `{ ...process.env }`.

### C. Recommendation challenges

- **Q1:** runtime check doesn't strip code; hook reach via preload; wrong user-data mechanism; **[Major]** a persistent bench profile makes runs dependent.
- **Q2 [Critical]:** 10 trap tasks × 1–2 traps can't cover 12 categories in both splits; drift and the decoy number dropped.
- **Q3 [Major]:** 7 datasets for 8 tasks; no wrangling dataset.
- **Q4 [Major]:** the private-path guard is a deny-list and dev keys are reproducible; custody is the only control.
- **Q5 [Major]:** re-running agent notebooks in `bench/env` runs agent code unsandboxed.
- **Q6:** unbounded `issues[]`. **Q7:** no run-count mode; "median" undefined. **Q8 [Major]:** fixture splits and predicates. **Q10:** no reference for the 1-point rule. **Q11:** EC12-5 not amended.

### D–F. Buildability, operability, measurability

- **[Major]** Key hashes mismatch across machines without canonical serialisation and fixed threads.
- **[Major]** Task failure statuses, ledger reserve/settle and locking, and an immutable run directory undefined.
- **[Major]** EC12-2 included metrics whose data arrives later (M-05, M-11, M-13, M-14).
- **[Major]** M-07 and M-08 had no agent-independent test set; the reference model was undefined.
- **[Minor]** Unverified facts (session marker variable, temperature support) not routed to docs-researcher.

### G. Safety

1. **[Major]** A data value makes the analyst ask the judge to quote key values into a committed rationale.
2. **[Major]** Shell keys reach the app through an inherited env.
3. **[Major]** Notebook re-runs in `bench/env` execute planted code with network and keys.
4. **[Major]** M-12 reads 0 when a guard declines the injected action.
5. **[Major]** Trap categories leak through file and column names.
6. **[Minor]** Agent prose embedded in committed summaries.

### H–K. Statistics, consistency, completeness, scope

- **[Major]** Public classics are memorised; M-03 penalises correct warnings on real data issues; surface forms needed for the holdout.
- **[Minor]** Score paths disagree; inputs exist only after P10's work merges; settings deny rules for paid entry points missing; "prompt and skill versions" undefined; size M too small; undefined terms; dependence on P11 Q-D1.

## Questions for the maintainer (defaults applied)

- **Q-E1. Baseline before P14.** Default: a **partial** baseline from a runner-written event log (cost, time, injection attempts, the rubric score); answer-based metrics start at P14's first gate. No bench-only prompt is added to today's analyst. **Agreed (2026-10-04).**
- **Q-E2. Trap coverage.** Default: 2 traps per dev task and 3 per holdout task, so all 12 categories appear in both splits at no extra cost; drift is listed as a v1.0 limitation. **Agreed (2026-10-04).**
- **Q-E3. P12 spend.** Default (updated in round 3): **≈ $13** (5 dev tasks per provider ≈ $11, judge pilot ≈ $2), hard-blocked until a maintainer approves it. **Agreed after discussion (2026-10-04).**
- **Q-E4. Holdout custody.** Default: holdout tasks, seeds and keys live outside the repo with the maintainers; results for them are committed as aggregates only. **Agreed (2026-10-04).**
- **Q-E5. Committed journals.** Default: official dev runs commit their journals and CI re-scores them (synthetic and public data only). **Agreed (2026-10-04).**
- **Q-E6. Notebook re-runs.** Default: only inside DataDesk's compute sandbox (or a no-network, empty-env child), never in the reference env. **Agreed (2026-10-04).**
