## 1. Intent

Execute the audited phase plans **as written** (no rescoping), in an order that avoids rework,
with the two-maintainer model the owner chose (P12 Q-K2). This spec decides only three things
the plans leave open or get wrong; every other detail stays in the phase plans.

1. **Phase order:** P10 → P11 → **P13 → P12** (the roadmap lists P12 before P13).
2. **Maintainer roles:** maintainer 2 writes and holds the holdout generator; the owner runs the
   holdout oracle pass.
3. **Stop points:** where execution halts for the owner, beyond the normal end-of-phase stop.

## 2. Decisions

### 2.1 P13 runs before P12

**Why.** P12's reference env is pinned to the compute host's library versions, which P13 hands
over once, at P13-08. P12 session 1 needs them. P13 depends only on P11 and spends $0, and P14
needs both P12 and P13, so moving P13 forward delays nothing. On a P13 no-go, P13b (CPython in an
AppContainer) runs before P12 and P12 gets CPython's versions; with the roadmap order, that case
would force P12's keys and golden vectors to be regenerated.

**Rejected.** (a) Roadmap order with a provisional Pyodide pin, re-pinned at P13-08: rework and
key drift (R-19), worse on a no-go. (b) P12 and P13 in parallel: still blocked on P13-08 and
breaks CLAUDE.md "one phase at a time".

**Record.** A D-NNN in P10's first commit. Phase numbers and branch names are unchanged.

### 2.2 Maintainer roles

- **Maintainer 2** writes the holdout generator's surface-form code, seeds, task files and keys,
  holds them outside the repo, and commits only salted commitments (P12-05). They are also the
  non-author for the CONTRIBUTING walkthrough (EC10-6) and a code owner of
  `bench/spend/maintainers/`.
- **The owner** runs the holdout oracle pass (P12-16, EC12-8), creates the signed spend tags, and
  runs every paid pass interactively.
- **Why this split:** the holdout stays blind to whoever builds most of the bench code, the
  strongest available guard against overfitting (R-08).

**Required input:** maintainer 2's GitHub handle and signing public key, supplied by the owner
before P10-08 starts. P10-08 is blocked without it.

**Record.** A D-NNN in P10's first commit.

### 2.3 Spend-approval source

P12 Q-K1 replaces D-034's "remote phase branch" approval with maintainer-signed annotated tags
`spend/<phase>/<contributor>/<amount>`. Recorded as a D-NNN at P12 sign-off, as the P12 plan says.

## 4. Invariants across all steps

- No automated test makes a real API call (`tests/setup/no-network.ts`).
- Fast-moving SDK facts are verified by docs-researcher and cited in `DECISIONS.md` before use.
- Judge scores stay local and marked uncalibrated until P16's calibration.
- No committed file holds a holdout task, seed or key.
- The next phase starts only after the owner merges the previous phase's PR.
